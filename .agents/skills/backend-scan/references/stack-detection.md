# Stack Detection and Fact Extraction

Read this in backend-scan Step 2. Detection is by reading manifests and source; never run the project to find out. When a signal is absent or ambiguous, record `unknown` instead of guessing.

## Exclusions

Skip these when finding or searching files. They are vendored, generated or build output:

- `node_modules/`, `vendor/`, `.venv/`, `venv/`, `env/`, `__pycache__/`, `.tox/`, `site-packages/`
- `dist/`, `build/`, `out/`, `target/`, `bin/`, `obj/`, `.next/`, `.nuxt/`, `coverage/`, `.gradle/`
- `.git/`, `.opencode/everything-backend-memory/`, `.idea/`, `.vscode/`
- Lockfiles: read them only to identify the package manager and resolved versions, never in full.

Generated-code markers (record as generated, do not extract conventions from them): headers such as `Code generated ... DO NOT EDIT`, `@generated`, `autogenerated`; folders named `generated/`, `gen/`, `__generated__/`; Prisma client output; protobuf/gRPC stubs (`*_pb2.py`, `*.pb.go`); OpenAPI client folders.

## Directory Structure Hints

Common folder names per layer. Use them to map structure and guess the architecture style; confirm by reading a file or two in each.

- Source roots: `src/`, `lib/`, `app/`, `internal/`, `cmd/`, `pkg/`
- Transport: `controllers/`, `handlers/`, `routes/`, `api/`, `resolvers/`
- Domain and data: `models/`, `entities/`, `schemas/`, `domain/`
- Business logic and data access: `services/`, `use-cases/` / `usecases/`, `repositories/`, `daos/`
- Cross-cutting: `middleware/`, `guards/`, `interceptors/`, `config/`, `settings/`, `utils/`, `helpers/`
- Style hints: `domain/` + `adapters/` or `ports/` suggests hexagonal; `modules/<feature>/` with its own layers suggests a modular monolith; several `services/<name>/` each with a manifest suggests microservices.

On a large codebase, start from the source roots and entry points and sample representative files per layer.

## Other Infrastructure Signals

- Database: env example files (`.env.example`, `.env.sample`), `docker-compose*.yml` services, connection-string prefixes (`postgres://`, `mysql://`, `mongodb://`). Never read real secret files (`.env`, credentials) beyond confirming they exist.
- Cache / queue / search: Redis, RabbitMQ (`amqplib`, `pika`), Kafka, SQS, BullMQ, Celery, Sidekiq, Elasticsearch / OpenSearch clients.
- Auth: JWT libraries, Passport, OAuth/OIDC clients, session middleware, framework auth modules.
- Deploy hints (record for the summary only; deployment.md belongs to backend-deploy): `Dockerfile`, `.github/workflows/`, `.gitlab-ci.yml`, Helm charts, Terraform.

## Extraction Recipes

Keep a source path for every fact. If a fact needs a running database or app, record `unknown`.

### Tables and relationships (db-schema.md)
1. Prefer the declarative schema: `schema.prisma`, Drizzle schema files, SQLAlchemy / Django models, JPA `@Entity` classes, Ecto schemas, EF `DbContext`, `db/schema.rb`, `ent/schema/`.
2. Else reconstruct from migrations in order (Alembic versions, Flyway `V*__`, Rails `db/migrate`, `prisma/migrations/*/migration.sql`). Note the migrations tool and the latest migration id.
3. Record tables or collections, primary keys, foreign keys, unique constraints and indexes you can see. Mark relationships inferred from naming only as `inferred`.

### Endpoints and conventions (api-patterns.md)
1. Look for a spec first: `openapi.*`, `swagger.*`, `*.graphql` / `schema.graphql`, `*.proto`. If one exists, record it as the contract source.
2. Else search for route registration: `app.get(` / `router.post(` (Express/Koa/Hono), `@Get(` / `@Controller(` (NestJS), `@app.get` / `APIRouter` (FastAPI), `urlpatterns` (Django), `r.Get(` / `HandleFunc(` (Go), `@GetMapping` / `@RequestMapping` (Spring), `routes.rb`, `Route::` (Laravel), `MapGet` (.NET), `scope "/api"` (Phoenix).
3. Record protocol, base path and version prefix, auth mechanism, pagination style, error response shape (shared error class or middleware), validation library, and naming conventions. Keep an endpoint inventory if it is small; for large APIs, record counts per module plus the spec or router file paths.

### Decisions (decisions.md)
- Read existing ADRs (`docs/adr/`, `docs/decisions/`, `adr/`) and `docs/architecture/`. Link them; don't copy them in full.
- Only infer a decision when the code makes it unambiguous (for example "PostgreSQL via Prisma"). Inferred decisions are `Proposed`, never `Accepted`.

### Issues (issues.md)
- Count `TODO`, `FIXME`, `HACK` markers per module. Record one aggregated Low issue per module, not one per marker.
- Do not grade security, performance or design quality here; that belongs to backend-doctor and backend-security.
