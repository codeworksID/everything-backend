# Secure Coding Baseline

> **Single source of truth** for writing backend code that survives hostile input, outside the database layer. Queries follow `sql-safety.md`; everything else follows this file. Every skill that writes, reviews, tests or fixes code applies both: backend-implement, backend-refactor, backend-debug, backend-auth, backend-api-design, backend-test, backend-doctor, backend-security, backend-ops and backend-deploy. A skill may add stack detail but must not weaken these rules. Rule numbers (S1-S18) are stable; other skills and `scripts/security-scan.js` cite them.

**Untrusted** means anything the service did not compute itself from trusted state: request paths, query strings, bodies, GraphQL variables, headers (including `Host`, `X-Forwarded-*`, `Origin`, `Referer`), cookies, unverified token claims, file names and contents, queue messages, webhooks, third-party API responses, environment-supplied URLs that users can influence, and data read back from the database that a user originally wrote. A public endpoint is reachable by an attacker who reads your OpenAPI spec and your frontend's JavaScript.

## The Rules

### Input, objects and access

**S1. Validate every input at the boundary, by allowlist.** One schema per endpoint (Zod, Pydantic, Bean Validation, `binding:` tags, FluentValidation) checks type, length, range, format and enum membership before the service layer runs. Reject unknown fields (`.strict()`, `extra="forbid"`, Jackson `FAIL_ON_UNKNOWN_PROPERTIES` enabled (Spring Boot turns it off by default: set `spring.jackson.deserialization.fail-on-unknown-properties=true`), Go `DisallowUnknownFields`). Reject arrays or objects where a scalar is expected. Normalize Unicode (NFKC) before comparing identifiers such as usernames and emails. Validation narrows the attack surface; it never replaces S2-S10 or `sql-safety.md`.

**S2. No mass assignment, no over-exposure.** Never bind a request body straight onto a persistence model (`Model.create(req.body)`, `data: req.body`, `Object.assign(entity, req.body)`, `**request.json`, `params.permit!`, `$guarded = []`). Copy allowlisted fields into an input DTO; fields such as `role`, `isAdmin`, `tenantId`, `ownerId`, `balance`, `status`, `emailVerified` and `price` are set by the server only. Responses go through an output DTO or serializer allowlist: never return password hashes, tokens, internal flags, other users' PII or full database rows.

**S3. Deny by default; check object and function access on every request.** Every route is authenticated unless it is on an explicit public allowlist. Object access binds the owner from the authenticated principal (`sql-safety.md` rule 3). Function access (admin, billing, export, impersonation, bulk endpoints) checks a role or permission on the server, not a hidden UI button or a client flag. Return 404 for objects the caller may not see. State changes that must happen once (balances, stock, coupons, single-use tokens, invites) are atomic: a conditional update (`UPDATE ... SET balance = balance - $1 WHERE id = $2 AND balance >= $1`), a row lock or a unique constraint, plus an idempotency key on the request, never read-check-write in application code (race conditions, TOCTOU). The design lives in backend-auth -> `references/authorization.md`.

### Injection beyond SQL

**S4. No shell, no command strings.** Run programs with an argument array and the shell off: Node `execFile`/`spawn(cmd, args)` (never `exec`, never `shell: true`), Python `subprocess.run([...], shell=False)` (never `os.system`/`os.popen`), Go `exec.Command(prog, args...)` (never `"sh", "-c"`), Java `ProcessBuilder(List)`, .NET `ProcessStartInfo` with `ArgumentList`. The program path is a constant. User values that become arguments are validated against a strict pattern, and an `--` separator is passed before them when the tool supports it, so `-oProxyCommand=...` style option injection cannot happen. Prefer a library over shelling out (image processing, archives, git).

**S5. Paths and uploads stay inside their folder.** Never pass a user value into a filesystem path without containment: resolve the full path (`path.resolve`, `os.path.realpath`, `filepath.Clean` + `filepath.Rel`, `Path.toRealPath`), then check it is inside the allowed base directory, and reject `..`, absolute paths, NUL bytes, and drive or UNC prefixes. Better: store files under server-generated names (UUID) and keep the original name only as metadata. Uploads have a size limit enforced while streaming, an allowlist of types checked by magic bytes (not the extension or `Content-Type`), are stored outside the web root or in object storage with no execute permission, are served with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff`, and are malware-scanned when users share them. SVG, HTML and XML uploads are never served inline from the app's own origin (stored XSS): serve them from a separate cookieless domain, convert them, or sanitize them. Archive extraction checks every entry path (zip slip; Python 3.12+ `tarfile` `filter="data"`) and caps the total uncompressed size and entry count (zip bombs).

**S6. Outbound requests do not go where the user says (SSRF).** If a URL, host or webhook target comes from input, allow only `https`, resolve the host, normalize each resolved address (IPv4-mapped IPv6 such as `::ffff:127.0.0.1` back to IPv4; decimal, octal and hex IPv4 forms), and reject loopback, private (RFC 1918, `fc00::/7`), link-local (`169.254.0.0/16`, including the cloud metadata address `169.254.169.254`, `fe80::/10`), CGNAT `100.64.0.0/10`, `0.0.0.0/8`, `192.0.0.0/24` (Oracle Cloud metadata at `192.0.0.192`), `198.18.0.0/15`, IPv4-mapped `::ffff:0:0/96` and NAT64 `64:ff9b::/96`, for every resolved address. A vetted library (for example `ipaddr.js` range checks, Python `ipaddress` `is_global`) beats a hand-written list. Connect to the address you checked (pin it) so DNS rebinding cannot swap it, disable redirects or re-validate each hop, set connect and total timeouts and a response size cap, and never return the raw response body or error to the caller. Prefer an allowlist of hosts over a blocklist. On cloud, require IMDSv2 (AWS) or the metadata header so a plain GET to the metadata service fails.

**S7. Only parse data formats that cannot run code.** Use JSON with a schema. Never deserialize untrusted bytes with `pickle`/`cPickle`/`dill`/`joblib`/`marshal`/`shelve`, `yaml.load` without `SafeLoader` (use `yaml.safe_load`), `jsonpickle`, Java `ObjectInputStream`/`XMLDecoder`, Jackson default typing, .NET `BinaryFormatter`/`NetDataContractSerializer`/`LosFormatter`/`SoapFormatter` or Json.NET `TypeNameHandling` other than `None`, PHP `unserialize`, Ruby `Marshal.load` or `YAML.unsafe_load`, `node-serialize`, or `torch.load` on untrusted files (prefer safetensors; `weights_only=True` is only safe on PyTorch >= 2.6, see CVE-2025-32434). XML parsers disable DTDs and external entities (XXE): Python `defusedxml`, Java `disallow-doctype-decl` = true, .NET `DtdProcessing.Prohibit` with `XmlResolver = null`, libxml without `NOENT`.

**S8. Never evaluate data as code or templates.** No `eval`, `new Function`, `vm.run*`, `setTimeout(string)`, Python `eval`/`exec`, Ruby `instance_eval` with strings, PHP `eval`/`create_function`/`assert($x)`. Templates are fixed files: never compile a template from user input (`render_template_string(request...)`, `Template(user_text)`, `ejs.render(input)`, `Handlebars.compile(input)`: server-side template injection). Expression languages (SpEL, OGNL, MVEL, JEXL) never evaluate user strings. Use a parser, a lookup table or a safe expression library with a fixed function set. The same holds for other query languages: LDAP filters escape values (RFC 4515: `*`, `(`, `)`, `\`, NUL) or use the library's filter builder, XPath uses variables, not string building, and NoSQL filters follow `sql-safety.md` rule 9.

**S9. Encode output for its context.** HTML is rendered by an auto-escaping template engine; `innerHTML`, `dangerouslySetInnerHTML`, `v-html`, `|safe`, `mark_safe`, `Markup`, `html_safe`, `Html.Raw` and `{{{ }}}` take only HTML sanitized by a vetted library (DOMPurify, bleach/nh3, OWASP Java HTML Sanitizer). APIs return `application/json` with `X-Content-Type-Options: nosniff`, never user input echoed as `text/html`. Response headers reject CR and LF in values (header injection, response splitting). Redirect targets are relative paths or allowlisted hosts (open redirect); reject `//evil.com` and `/\evil.com`. Log lines escape or strip CR/LF from user values (log injection). CSV exports defuse formula injection: prefix a cell that starts with `=`, `+`, `-`, `@`, tab, CR, LF or their full-width forms (`＝＋－＠`) with `'`, wrap every field in double quotes and double embedded quotes. Emails escape user values in HTML bodies and reject CR/LF in header fields.

**S10. No user-controlled regexes, no prototype pollution.** Never compile a regular expression from input; escape it as a literal (`escapeRegExp`, `re.escape`, `regexp.QuoteMeta`, `Pattern.quote`) or use a linear-time engine (RE2, Go `regexp`, .NET `RegexOptions.NonBacktracking`) with a length cap. Review your own patterns for nested quantifiers (`(a+)+`, `(.*a){n}`) that backtrack exponentially (ReDoS), and set a match timeout where the engine supports it. In JavaScript, never deep-merge, `_.set` or path-assign request data onto objects: validate with a schema first, reject `__proto__`, `constructor` and `prototype` keys, and use `Object.create(null)` or `Map` for dictionaries keyed by user input.

### Authentication, crypto and secrets

**S11. Credentials and tokens are handled by the book.** Passwords are hashed with argon2id (preferred), scrypt or bcrypt (cost >= 10; bcrypt truncates input at 72 bytes), or PBKDF2-HMAC-SHA256 with >= 600,000 iterations where FIPS is required; never MD5, SHA-1 or plain SHA-256, salted or not. JWTs are verified (never just decoded) with a pinned algorithm list, the right key, and `exp`, `iss` and `aud` checked; reject `alg: none` and HS/RS confusion. Header fields `kid`, `jku`, `x5u` and `jwk` never choose the key source: `kid` only selects among keys from your configured JWKS URL or key store. Login, password reset, OTP and API-key endpoints are rate-limited per account and per IP, and their responses do not reveal whether an account exists. Reset, invite and magic-link tokens are random (S12), single-use, short-lived (<= 1 hour) and stored hashed. Sessions rotate their id on login and privilege change and are invalidated on logout and password change. Compare secrets, HMACs and tokens in constant time (`crypto.timingSafeEqual`, `hmac.compare_digest`, `subtle.ConstantTimeCompare`, `MessageDigest.isEqual`, `CryptographicOperations.FixedTimeEquals`). Details: backend-auth.

**S12. Use vetted crypto and real randomness.** Security values (tokens, ids in URLs, reset codes, salts, nonces, API keys, session ids) come from a CSPRNG: `crypto.randomBytes`/`randomUUID`, Python `secrets`, Go `crypto/rand`, Java `SecureRandom`, .NET `RandomNumberGenerator`; never `Math.random`, `random`, `math/rand`, `java.util.Random`, `rand()`. Encrypt with AEAD (AES-256-GCM or ChaCha20-Poly1305) through a high-level library (libsodium, Tink, `cryptography`'s AESGCM/Fernet); never ECB, DES, 3DES, RC4, Node `createCipher` (it derives the key and a fixed IV from the password with MD5; removed in Node 22), or a reused or constant IV/nonce. Never write your own crypto or token format. TLS verification is never disabled in code that ships (`rejectUnauthorized: false`, `verify=False`, `InsecureSkipVerify`, trust-all managers, `sslmode=disable` to a remote database): fix the CA bundle instead. Keys live in a KMS or secret manager and are rotatable.

**S13. Secrets never live in code.** No credentials, keys, tokens, connection-string passwords or private keys in source, tests, fixtures, Dockerfiles, CI files, OpenAPI examples or client bundles. Load them at runtime from the environment or a secret manager; commit only `.env.example` with placeholders. Different secrets per environment. Secrets never appear in logs, error messages, URLs (query strings end up in access logs), analytics or exception trackers. A secret that was ever committed is rotated, even if the commit was rewritten. Scanning and history checks: backend-security -> `references/secrets-and-supply-chain.md`.

### Browser-facing, limits and integrations

**S14. Cookies, CORS, CSRF and headers are explicit.** Session and auth cookies are `HttpOnly`, `Secure`, `SameSite=Lax` (or `Strict`) and host-only (`__Host-` prefix when possible). CORS lists exact origins; never `*` or a reflected `Origin` together with credentials, and never a `null` origin. Cookie-authenticated, state-changing endpoints require a CSRF token or a verified `Origin`/`Sec-Fetch-Site` check; pure bearer-token APIs do not use cookies at all. Set `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy` (`default-src 'none'; frame-ancestors 'none'` for JSON APIs), `Referrer-Policy` and `Cache-Control: no-store` on responses with personal data. Remove `X-Powered-By` and version banners.

**S15. Every resource is bounded.** Request body size limits per route (smaller for JSON than for uploads), pagination with a server-side maximum page size, timeouts on every outbound call and database query, rate limits on expensive and unauthenticated endpoints (keyed on the client IP only after the framework is configured with the exact trusted proxy hops, for example Express `trust proxy` set to a number or subnet, never `true`; otherwise a spoofed `X-Forwarded-For` resets the limit), caps on batch sizes, array lengths, string lengths, nesting depth, GraphQL depth/complexity/aliases, decompressed size, and per-tenant quotas for jobs and storage. Unbounded work for one request is a denial of service waiting to happen. Infrastructure side: backend-ops.

**S16. Webhooks and third-party data are verified and validated.** Incoming webhooks verify the provider's HMAC or signature over the **raw** request body with a constant-time compare, reject timestamps older than ~5 minutes, and de-duplicate by event id (replay). Never trust webhook fields you can fetch from the provider's API instead. Responses from third-party APIs are untrusted input: validate them with a schema, cap their size, set timeouts, and never pass them into SQL, shell, templates, redirects or `eval`.

### Errors, logging and the supply chain

**S17. Fail closed and quietly.** Errors return a generic message, a stable error code and a correlation id; stack traces, SQL, driver messages, file paths and internal hostnames stay in server logs. Debug modes, developer exception pages, interactive consoles, `/actuator` and admin UIs are off or authenticated in production. An exception inside an authorization or validation check denies the request. Log security events (logins, failures, permission denials, admin actions, key changes) with actor, action, target and outcome, without passwords, tokens, keys, full card numbers or unneeded PII.

**S18. Dependencies and pipelines are pinned and minimal.** Lockfiles are committed and installs use them (`npm ci`, `pip install --require-hashes`, `go mod verify`). No `curl | sh`; download pinned versions and verify checksums. Base images are pinned to a version or digest and run as a non-root user. CI actions are pinned to a full commit SHA, `permissions:` are least-privilege, untrusted pull requests get no secrets, `pull_request_target` never checks out PR code, and attacker-controlled GitHub context (`github.event.*.title`, `body`, `head_ref`) is passed through `env:`, never interpolated into `run:`. New dependencies are checked for maintenance, typosquatting and install scripts before adding. Details: backend-security and backend-deploy.

## Safe vs Unsafe APIs per Stack

| Concern | Node / TypeScript | Python | Go | Java / Kotlin | .NET |
|---|---|---|---|---|---|
| Run a program (S4) | `execFile(bin, args)`, `spawn(bin, args)` / `exec`, `shell: true` | `subprocess.run([...])` / `os.system`, `shell=True` | `exec.Command(bin, args...)` / `"sh", "-c"` | `ProcessBuilder(List)` / `Runtime.exec(String)` | `ProcessStartInfo.ArgumentList` / `cmd.exe /c` |
| Contain a path (S5) | `path.resolve` + `startsWith(base + path.sep)` | `Path(base, x).resolve().is_relative_to(base)` | `filepath.Rel` + no `..`, or `os.Root` (Go 1.24+) | `base.resolve(x).normalize().startsWith(base)` (a `Path` compare, not a string prefix) | `Path.GetFullPath` + `StartsWith(base + Path.DirectorySeparatorChar, StringComparison.Ordinal)` |
| Parse data (S7) | `JSON.parse` + Zod / `node-serialize`, `eval` | `json`, `yaml.safe_load`, `defusedxml` / `pickle`, `yaml.load` | `encoding/json` / `encoding/gob` from untrusted peers | Jackson without default typing / `ObjectInputStream` | `System.Text.Json` / `BinaryFormatter`, `TypeNameHandling.All` |
| Random token (S12) | `crypto.randomBytes(32)`, `randomUUID()` / `Math.random()` | `secrets.token_urlsafe(32)` / `random.*` | `crypto/rand` / `math/rand` | `SecureRandom` / `Random` | `RandomNumberGenerator` / `Random` |
| Password hash (S11) | `argon2`, `bcrypt` / `createHash('sha256')` | `argon2-cffi`, `passlib`, `bcrypt` / `hashlib` | `x/crypto/argon2`, `bcrypt` / `sha256` | Spring `Argon2PasswordEncoder`, `BCryptPasswordEncoder` / `MessageDigest` | Identity `PasswordHasher` with `IterationCount` raised (V3 default 100,000 PBKDF2-SHA512 is below OWASP's 210,000), `Rfc2898DeriveBytes.Pbkdf2` / `SHA256` |
| Compare secrets (S11) | `crypto.timingSafeEqual` / `===` | `hmac.compare_digest` / `==` | `subtle.ConstantTimeCompare` / `==` | `MessageDigest.isEqual` / `equals` | `CryptographicOperations.FixedTimeEquals` / `==` |
| JWT (S11) | `jwt.verify(t, key, { algorithms: [...] })`, `jose.jwtVerify` / `jwt.decode` | `jwt.decode(t, key, algorithms=[...], audience=...)` / `verify_signature: False` | `jwt.Parse` with `WithValidMethods` / `ParseUnverified` | `JwtParser.verifyWith(key)` / unsigned parse | `TokenValidationParameters` with `RequireSignedTokens`, `ValidAlgorithms`, `ValidateIssuer`, `ValidateAudience` and `ValidateLifetime` on / any of them off |
| HTML output (S9) | auto-escaping templates, DOMPurify / `innerHTML`, `dangerouslySetInnerHTML` | Jinja2 autoescape, `nh3` / `\|safe`, `Markup` | `html/template` / `text/template` for HTML, `template.HTML(x)` | Thymeleaf `th:text` / `th:utext` | Razor `@x` / `Html.Raw` |

Ruby and PHP follow the same split: `Open3.capture2(bin, *args)` not backticks, `JSON.parse` not `Marshal.load`, `SecureRandom`, `ActiveSupport::SecurityUtils.secure_compare`; `proc_open([...])` with an array (PHP 7.4+) not `shell_exec`, `json_decode` not `unserialize`, `random_bytes`, `hash_equals`, `password_hash(PASSWORD_ARGON2ID)`.

## Verification (required before a change is reported as done)

1. **Scan.** Run `node <shared>/scripts/security-scan.js --changed` (add `--base <main branch>` for a whole branch). Every critical or high hit is fixed, or justified in the code with `// security-scan: ignore <rule-id> <reason>` and listed in the summary. Medium hits are read and either fixed or explained. The scanner is line based: it is a floor, not proof.
2. **Read the changed code against S1-S18** and `sql-safety.md`, especially multi-line flows the scanner cannot follow (a request value stored in a variable, then passed to a sink three lines later or in another file).
3. **SAST when available.** `semgrep scan --config p/default --config p/secrets --config p/<language> --metrics=off`; Bandit, gosec, Brakeman, SpotBugs + Find Security Bugs, `eslint-plugin-security` (installing a tool is Always Ask First).
4. **Negative tests** (backend-test -> `references/security-tests.md`) for each changed endpoint, covering the classes it touches: another user's id (404), unknown and privileged fields in the body (`role`, `tenantId`: ignored or 400), oversized and deeply nested bodies (413/400), path traversal (`../../etc/passwd`, `..%2f`, `%00`), SSRF targets (`http://169.254.169.254/`, `http://127.0.0.1:22`, `http://[::1]`, a redirect to localhost), command and template payloads (`; id`, `$(id)`, `{{7*7}}`, `${7*7}`), XSS payloads in fields that are rendered (`<script>`, `"><img src=x onerror=alert(1)>`), open-redirect targets (`//evil.example`), CR/LF in header-bound values, unsigned or replayed webhooks (401), expired, `alg: none` and wrong-audience JWTs (401), and the login/reset rate limit (429).
5. **Exit criterion.** A change with an unresolved critical or high scan hit, a missing owner or role check, or a violated S-rule on a reachable code path is **not done**. Severity in review: Critical when exploitable from a public or low-privilege endpoint without user interaction (injection, auth bypass, SSRF to metadata, RCE, leaked secret); High when it needs a privileged account or an unusual condition; Medium for missing hardening (headers, limits, cookie flags) that makes another bug easier to exploit.
